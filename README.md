# 🍺 BG Советник — локальный LLM-помощник для Hearthstone Battlegrounds

Оверлей поверх Hearthstone, который читает `Power.log`, отслеживает состояние
Полей сражений (магазин Боба, доска, рука, золото, тир таверны, здоровье)
и даёт советы по закупке через локальную LLM (Ollama). Игра за вас **не играет** —
только подсказывает, поэтому риска бана нет.

## Состав

| Файл | Назначение |
|---|---|
| `main.py` | точка входа: лог-наблюдатель + оверлей + советник |
| `log_watcher.py` | парсер Power.log (сущности, фазы, магазин, доска) |
| `advisor.py` | сборка промпта и запрос к Ollama |
| `overlay.py` | полупрозрачное окно поверх игры (PySide6) |
| `bg_db.json` | база знаний: стратегические заметки + существа (пополняется) |
| `config.json` | настройки (модель, путь к логам, оверлей) |
| `test_parser.py` | офлайн-проверка парсера на существующем логе |
| `test_e2e.py` | сквозной тест: лог → совет LLM |
| `history.py` | память матча: история ходов в промпте советчика |
| `gen_dataset.py` | офлайн-разметка старых Power.log через LLM (датасет для классификатора) |
| `labels.py` | конвертация советов LLM в типизированные метки (buy_slot/reroll/upgrade/freeze/comp) |
| `features.py` | кодирование состояния в признаки: текст для Laya + вопросы с вариантами |

## Установка (уже сделано на этом ПК)

```bat
pip install -r requirements.txt
ollama pull qwen3:8b
```

## Запуск

1. Запустите сервер Ollama: `ollama serve` (или просто запущенное приложение Ollama в трее).
2. Запустите советника: `python main.py` (или двойной клик по `run.bat`).
3. Запустите Hearthstone и начните партию Полей сражений.
4. Окно-оверлей появится поверх игры: состояние обновляется само,
   совет — по кнопке «💡 Совет» или автоматически при начале закупки
   (настраивается `auto_advice` в `config.json`).

Играйте в оконном или оконном безрамочном режиме — в эксклюзивном
полноэкранном режиме оверлей не виден.

## Настройки (`config.json`)

- `hearthstone_logs_dir` — папка логов HS (уже прописана: `G:\Hearthstone\Logs`);
- `ollama_url`, `model` — адрес Ollama и модель (по умолчанию `qwen3:8b`);
- `auto_advice` — автоматически спрашивать совет при смене магазина;
- `history_turns` — сколько последних ходов матча видит советчик (память: триплеты, планы);
- `dataset_log` — писать снапшоты и советы в `dataset/*.jsonl` для дистилляции в классификатор;
- `fast_mode`, `clf_threshold`, `clf_path` — каскад «классификатор → LLM»: порог уверенности и путь к чекпоинту;
- `overlay` — прозрачность, ширина, «поверх всех окон».

## Датасет для классификатора

Советчик пишет сырую разметку в `dataset/` (в `.gitignore`, в репозиторий не
попадает): `snapshots.jsonl` — все снапшоты закупок, `advice.jsonl` — пары
«снапшот + совет LLM». Туда же умеет дописывать офлайн-генератор — он
прогоняет старые Power.log через парсер и спрашивает совет на каждую закупку:

```bat
python gen_dataset.py                  # все логи из hearthstone_logs_dir
python gen_dataset.py --max-per-log 20 # пробный прогон, по 20 снапшотов с лога
```

Повторный запуск не дублирует уже размеченные снапшоты. Цепочка до
классификатора: `gen_dataset.py → labels.py (метки) → features.py (признаки)
→ train_classifier.py (обучение голов на CPU, минуты) → checkpoints/bg_clf`.
Инференс — `classifier.py`: ~0.1–0.2 с на CPU против секунд у LLM.

## Каскад «быстрый/умный» (fast_mode)

При `fast_mode: true` совет идёт каскадом: сначала энкодерный классификатор
(`classifier.py`, тот же ModernBERT, что в Laya) — если уверенность в выборе
слота ≥ `clf_threshold`, совет появляется мгновенно; если классификатор
неуверен или не обучен — отвечает LLM, как раньше. Кнопка «💡 Совет» всегда
даёт глубокий разбор LLM. Записи в датасете помечаются источником, саморазметка
классификатора из обучения исключается.

## Результаты классификатора (датасет 504 совета, holdout 91)

Обучение голов на замороженном энкодере, 8 эпох (~12 мин на CPU):

| Голова | Holdout | Комментарий |
|---|---|---|
| Цель сборки (12 классов) | **0.82** | большинство 0.45 — уверенно бьёт его |
| Покупка слота (9 классов) | 0.33 | порог 0.7 в каскаде: ~20% состояний получают мгновенный ответ (~0.6 точн.), остальные честно уходят в LLM |
| Ап/реролл/заморозка | н/д | метки почти пустые (LLM редко пишет эти слова) — закрыто fallback'ом |

Вывод: быстрый путь полезен прежде всего для сборки и явных покупок;
сомнительные состояния честно уходят в LLM. Качество растёт с датасетом:
переобучение — `labels.py && features.py && train_classifier.py` после
накопления новых логов (живой советчик пишет их сам, `dataset_log: true`).

## Как это работает

- Логирование Power включается файлом `%LOCALAPPDATA%\Blizzard\Hearthstone\log.config`
  (у вас уже включено). Логи пишутся в `Logs\Hearthstone_<дата_время>\Power.log`.
- Парсер следит за самым свежим Power.log и строит состояние: фаза
  (закупка/бой по `BACON_CURRENT_COMBAT_PLAYER_ID`), золото (`RESOURCES - RESOURCES_USED`),
  тир (`PLAYER_TECH_LEVEL`), магазин (существа Боба с тегом `HAS_DRAG_TO_BUY`),
  доска и рука (по зонам и контроллеру). Дополнительно: заморозка магазина
  (тег `FROZEN`), племена, точно присутствующие в пуле (попадались в магазине),
  следующий противник (`NEXT_OPPONENT_PLAYER_ID`, когда его герой материализован
  в логе) и сводка последнего боя (доска противника материализуется под
  контроллером Боба на время боя — племена и суммарные статы).
- Советник отправляет состояние + стратегическую справку из `bg_db.json`
  в локальную модель и показывает краткий совет на русском.
- Ответ валидируется: несуществующий «тир 7», ап при максимальном тире и
  небьющаяся арифметика золота ловятся автоматически, модель получает
  ошибку и отвечает заново (1 повтор). Стоимость апов таверны —
  `tavern_upgrade_costs` в `config.json`.

## Ограничения v1

- Советы зависят от силы модели: 8b заметно умнее 7b, но всё равно может ошибаться
  в деталях (проверяйте советы на здравый смысл); можно поставить модель крупнее
  (`qwen3:14b`, если хватит VRAM/RAM — на 8 ГБ видеокарте будет CPU-offload и медленнее).
- Текст баббла Боба и полный пул племён партии в Power.log не передаются
  (это клиентский UI) — вместо пула советнику даётся список племён, которые точно
  есть (попадались в вашем магазине). Заморозка лавки учитывается (тег `FROZEN`).
- Если советник запущен посреди партии, состояние достроится со следующей партии
  (или со следующего большого дампа состояния).
- База `bg_db.json` обновлена под патч 37.0.2 (2026-11-03) по официальным
  патчноутам Blizzard. После следующих патчей дополняйте `meta_notes_ru`,
  `strategy_ru` и `minions` — советы станут точнее.
